# v1.8 常吃搭配、做法提示与订阅提醒

## 已可在本机使用

- 单项食物收藏保留克数/毫升、生熟状态、完整营养及自定义标签快照。
- 整餐搭配可命名；今日顶部“我的常吃”选择餐次后一键追加，不覆盖原餐、不自动算吃过。无计划时自动创建空白记录。
- 加入后继续用原来的改量/换菜入口；已记录餐需取消记录后才能修改。
- 收藏最多 100 项，每餐 40 项；重复保存相同名称和快照不重复创建；写入失败不显示成功，异常旧数据不覆盖。
- 食物行显示做法，点“做法与称重”查看操作步骤。干燕麦、薯类、谷物、蔬菜和肉类分别说明。烤熟/焖熟肉条目只展示对应方法；不支持的即食/自定义食品按包装说明。
- 做法不改变营养值，不把一种熟重数据库数值当成所有做法的统一值。油、糖、调料和额外食材须另加。

烹调安全依据：[FoodSafety.gov 最低中心温度](https://www.foodsafety.gov/food-safety-charts/safe-minimum-internal-temperatures)。禽肉 74°C；绞肉 71°C；整块牛、猪、羊肉 63°C 后静置 3 分钟；鱼 63°C 或肉质不透明且容易分开。虾按不透明、珍珠白/白色判断。没有提供一概而论的烹调分钟数。

## 微信提醒：代码已准备，默认未启用

真实通知不是本机定时器。由用户主动点击触发 `wx.requestSubscribeMessage`，同意后服务端安排下一次提醒。不能把一次性订阅声称为永久每日授权；是否可申请长期模板由微信类目/模板规则决定，未作此假设。

“我的”页目前可保存希望提醒的时间。只有部署完成并打开功能开关，才出现可用订阅按钮。未配置时明确说明关闭小程序后不会收到推送。

### 部署所需

1. 完成 `docs/account-setup.md` 的真实 AppID 和云环境配置。
2. 在微信小程序后台订阅消息中选择符合业务类目的模板，取得模板 ID 和字段 key。把模板 ID 写入 `config/reminders.js`。
3. 创建数据库集合 `habitReminderJobs`、`habitReminderChecks`，两者客户端读写都禁止，只有云函数服务端访问；自定义规则为 `{"read": false, "write": false}`。不要使用“所有用户可读写”。
4. 部署 `cloudfunctions/habitReminder`（云端安装依赖），配置 `EXPECTED_APP_ID`、`REMINDER_TEMPLATE_ID`、`REMINDER_DATA_JSON`。模板 ID 必须与前端一致。数据 JSON 的 key 必须和实际获准模板一致，例如仅当该模板确实有这两个字段时才使用 `{"thing1":"记下今天的一小步","time2":"{time}"}`。支持 `{date}`、`{time}` 替换，文案需符合字段限制。
5. 确认配置里的 `subscribeMessage.send` 权限和 `habitReminderTimer` 定时触发器已部署；Cron `0 * * * * * *` 每分钟检查一次。每次处理最多 100 个到期任务，小规模验证后再评估容量和云资源用量。不开 HTTP 公网入口，定时器只能由平台触发。
6. 真机测试时按平台要求设置 `MINIPROGRAM_STATE`（体验版 `trial`、正式版 `formal`）；必须先验证消息跳转、模板合法性、真实接收与取消行为。
7. 验收通过后将 `config/reminders.js` 的 `enabled` 改为 true，再上传体验版。

官方 API：[订阅消息](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)、[用户主动订阅](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)。本次官方网页访问不稳定，客户端接口和 accept/reject/ban 状态另通过微信官方 `wechat-miniprogram/api-typings` 仓库核对；发布前仍以后台可用模板和真机结果为准。

### 行为与限制

- 使用北京时间 UTC+8。当前已过时间或今天已同步打卡则安排明天，否则安排今天。一位用户只保留一个待提醒任务，新订阅替换旧任务，不叠加多个时间。
- 同意订阅后同步的仅是“当前北京时间日期已打卡”的标记和提醒时间，不上传饮食/体重明细。未订阅者不会自动上传打卡状态；取消后停止主动同步。
- 已订阅用户完成打卡或重新进入今日页时重试同步。离线完成但未同步时，服务端不知道完成状态，可能仍发送；界面会提示同步失败。
- 微信日历与本机打卡采用不同日期时（例如设备在境外时区），只同步本机确有记录的北京时间日期，不能把昨天的打卡当作今天。用户界面标明提醒按北京时间。
- 服务端以可信 OPENID/APPID 确定用户，忽略客户端传来的身份。数据库按用户隔离。提醒编号不是登录凭证。
- 发送前再次检查是否打卡；已完成跳过。通过原子版本条件领取避免并发定时器重复发送。过期任务不补发。
- 消息发送失败或结果不确定时不自动重发，避免重复打扰；发送中进程中断需管理员核对，不能贸然重发。
- 取消无法撤回已发出/正在送达的消息。打卡和实际发送同时发生也存在短暂竞态，不能承诺绝对不会误提醒。
- 已同意订阅不代表微信保证送达，平台额度、模板、用户设置和网络都可能影响结果。
