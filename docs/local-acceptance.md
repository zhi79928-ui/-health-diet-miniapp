# v1.9 微信开发者工具验收

代码已进行 Node 逻辑 / 页面事件模拟测试与结构检查，以下原生界面需在微信开发者工具和真机确认。模拟测试不代表已通过微信审核。

## 更新方式

下载新版仓库 ZIP，解压到新目录并导入微信开发者工具，填写自己的 AppID。保留原项目以便回退；不要将原来的 project.private.config.json 或个人 AppID 提交到公共仓库。若使用同一个本地项目更新代码，保留缓存。切换开发者工具项目环境不保证共享原缓存。

## 按顺序体验

1. 编译后出现“今日、计划、食物、打卡、我的”五个底部入口；首次打开“今日”为空状态。
2. 在“计划”填入身高 180 cm、体重 180 斤、年龄 30 岁、男、中度活动、自动推荐，生成参考方案。选择维持或增重后重新生成，目标应变化。保存为今日计划，应跳转到“今日”。
3. 在午餐鸡胸肉上点击“换菜 / 改量”，选择“尽量保持蛋白质”和牛眼肉熟重条目。核对新克数、烹调状态、蛋白质近似保持，脂肪 / 热量和整餐合计随之更新。
4. 改成手动克数 200 g，确认；清空克数时应显示错误，不能确认。添加实际用油，整餐和全天合计应更新。
5. 记录早餐，“已摄入”只增加早餐，未记录午餐不计入。已记录餐的食物编辑按钮禁用；取消记录后可以修改，再次记录不会重复累加。
6. 保留已记录早餐，回“计划”重新生成保存，再回“今日”：早餐食物和数值应保持，未记录餐更新。
7. 关闭再打开，今日记录仍在；选择无记录历史日期应显示空状态。前一天有计划时可沿用，未记录状态重新开始，已有已记录餐不覆盖。
8. 添加食物时切换主食、蔬菜、水果分类，搜索“菜心”和“香蕉”，直接点选结果；只出现克数输入，不出现包装录入。分别测试“复制上一餐”和“复制昨日同餐”，复制后应保持待记录且允许改克数。
9. 在“打卡”输入 154 斤，保存后显示 77 kg；同日再次保存更新而非重复新增。补录昨天 78 kg，曲线应显示两个点，近七天均值为 77.5 kg（只有这两条时）。记录餐次后，近 7 天饮食趋势只按有记录日期计算。
10. 登录后主动备份，在数据库确认存在当前账号记录；删除云端备份后本机记录保留，数据库记录消失。重新备份、修改本机数据、恢复云端时应出现覆盖确认。
11. 在窄屏真机检查食物结果列表滚动、输入键盘、底部安全区、体重曲线及长名称换行。

## 边界与限制

- 记录基于本机日期；跨午夜操作应刷新到新日期，不能误写上一天。
- 保存失败必须提示，不能把未写入的数据显示为已保存。
- 不做自动云同步或用户行为上报；只有主动备份或订阅提醒时上传对应数据。删除缓存前仍需手动备份。
- 尚无自动过敏筛选、周食谱、支付会员或医学个体评估。
