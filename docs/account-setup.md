# 微信账号与云备份接入

## 本版范围

“我的”页提供主动同意后的微信身份验证和手动云备份。免登录仍可使用所有本机功能。不是手机号注册，不读取头像或昵称。未配置时明确显示账号服务暂未开放，不伪造登录成功。

登录不会自动上传健康记录。用户需主动点击“备份本机记录到云端”；恢复也需二次确认。备份包含健康设置、饮食日记、体重、打卡、自定义食物和常用餐，不包含提醒订阅状态。退出登录不会清除本机数据。

## 需要项目所有者提供的配置

1. 将 `project.config.json` 的 `touristappid` 替换为真实小程序 AppID。
2. 在微信开发者工具开通/选择同一小程序的云开发环境，填入 `config/cloud.js` 的 `envId`。
3. 在云数据库创建集合 `accountBackups`，客户端权限设为不可读、不可写，仅允许云函数服务端访问。
4. 部署 `cloudfunctions/accountLogin`，选择“云端安装依赖”。Node.js 18 或云平台支持的更新版本。
5. 为云函数配置环境变量 `EXPECTED_APP_ID`，值为该小程序 AppID。
6. 在真机依次验证登录、备份、修改一条本机记录、恢复；两个微信账号应得到不同编号且不能读取彼此的备份。

AppID 和环境 ID 可用于配置；无需提供 AppSecret、微信密码或短信验证码。

## 服务端边界

使用 CloudBase Node SDK 的 `app.auth().getUserInfo()` 读取可信上下文，并检查 `appId` 和 `openId`。不接收客户端传入的身份；返回的哈希账号编号仅用于显示，不是授权 token。后续每个数据接口都必须重新在服务端取当前调用者身份，不能根据页面上的登录状态授权。

本机只缓存用于展示的账号编号，不把它当作访问凭证。每次备份、查询和恢复都由云函数重新读取微信调用上下文并校验 AppID。云端记录以账号编号隔离，单份数据限制为 800 KiB；客户端不能直接读写 `accountBackups`。

依据：[CloudBase Node SDK 身份认证](https://docs.cloudbase.net/api-reference/server/node-sdk/auth)。接入仍需在真实 AppID 环境完成端到端验证。
