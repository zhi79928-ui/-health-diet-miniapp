# 微信账号接入（待环境部署）

## 本版范围

准备了“我的”页、主动同意后的微信身份验证和服务端云函数。免登录仍可使用所有本机功能。不是手机号注册，不读取头像或昵称。未配置时明确显示账号服务暂未开放，不伪造登录成功。

**本版没有云备份或多设备同步。** 本机饮食数据不属于账号空间；退出账号不会清除本机数据。登录验证是后续云备份的基础，目前不会因登录自动上传健康记录。若准备面向用户正式推广，应在备份恢复功能完成后再开放账号入口，避免让用户误以为记录已备份。

## 需要项目所有者提供的配置

1. 将 `project.config.json` 的 `touristappid` 替换为真实小程序 AppID。
2. 在微信开发者工具开通/选择同一小程序的云开发环境，填入 `config/cloud.js` 的 `envId`。
3. 部署 `cloudfunctions/accountLogin`，由开发者工具安装依赖。Node.js 18 或云平台支持的更新版本。
4. 为云函数配置环境变量 `EXPECTED_APP_ID`，值为该小程序 AppID。
5. 在真机调用登录，确认无配置、拒绝同意、离线和函数失败时不会显示成功；两个微信账号应得到不同编号。

AppID 和环境 ID 可用于配置；无需向助手提供 AppSecret、微信密码或短信验证码。本次没有开通付费资源、部署云函数或上传健康记录。

## 服务端边界

使用 CloudBase Node SDK 的 `app.auth().getUserInfo()` 读取可信上下文，并检查 `appId` 和 `openId`。不接收客户端传入的身份；返回的哈希账号编号仅用于显示，不是授权 token。后续每个数据接口都必须重新在服务端取当前调用者身份，不能根据页面上的登录状态授权。

前端登录态只保存在当前运行进程，不把缓存中的布尔值当作微信认证；重启应用须重新验证。退出会取消尚未完成的登录结果。本云函数不写数据库。

依据：[CloudBase Node SDK 身份认证](https://docs.cloudbase.net/api-reference/server/node-sdk/auth)。接入仍需在真实 AppID 环境完成端到端验证。
